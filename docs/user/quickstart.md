# Quick Start

## Python

This example invokes the Claude Code CLI, so `claude` must be installed and authenticated first.

```python
from py_agent_ctrl import AgentCtrl

response = AgentCtrl.claude_code().execute("Summarize this repository.")
print(response.text)
```

## CLI

This command invokes the Claude Code CLI, so `claude` must be installed and authenticated first.

```bash
uv run ctrlagent execute --agent claude-code "Summarize this repository."
```

## Structured Content

String prompts remain the default API:

```python
response = AgentCtrl.codex().execute("Review this repository.")
```

Advanced callers can attach typed content blocks. The bridge always keeps a
plain-text fallback, so unsupported providers still receive deterministic prompt
text instead of silently dropping context.

```python
from py_agent_ctrl import AgentCtrl, resource_link_block, text_block

response = (
    AgentCtrl.codex()
    .with_content(
        [
            text_block("Review this file and screenshot."),
            resource_link_block("file:///tmp/README.md", name="README.md"),
        ]
    )
    .with_image("/tmp/screenshot.png")
    .execute("")
)
```

Current provider-native lowering is intentionally conservative. Codex image
references are also passed as `--image`; other content is represented in the
prompt fallback unless a provider bridge explicitly documents native support.

## Stream Events

The stable event classes are `AgentTextEvent`, `AgentToolCallEvent`,
`AgentResultEvent`, and `AgentUnknownEvent`. Providers can also emit richer
events such as `AgentReasoningEvent`, `AgentPlanUpdateEvent`,
`AgentUsageEvent`, `AgentWarningEvent`, and `AgentFileChangeEvent` when their
native stream includes that information.

See [events.md](events.md) for the stable event contract, provider-specific
`raw` payload guidance, and streaming examples.

## Sessions

`AgentResponse.execution_id` is generated by `py-agent-ctrl` for each execution.
`AgentResponse.session_id` is the provider session/thread ID returned by the
agent CLI, when available.

Session helpers expose `SessionCapabilities`, `SessionInfo`, and
`SessionOperation` for callers that need to reason about resume/continue support
without assuming every provider supports listing, loading, forking, tagging,
renaming, or deleting sessions.

## Directories

`.in_directory(...)` sets the provider process working directory. The path is
expanded and resolved to an absolute path before the provider command is built;
missing working directories fail before the CLI is launched.

`.with_additional_dirs([...])` also resolves paths to absolute values. Relative
additional directories are resolved against `.in_directory(...)` when one is
set, otherwise against the current Python process directory.

Provider handling is native: Claude Code receives each entry as `--add-dir`,
Codex receives each entry as `--add-dir`, and providers without an additional
directory flag keep the values in the normalized request but do not pass them to
the CLI.

## Capabilities

`AgentCtrl.<agent>().capabilities()` returns `BridgeCapabilities`, which
describes provider-level behavior before launching the CLI. In addition to the
agent type, CLI name, session resume/continue flags, and supported option names,
capabilities expose concrete stream features such as `supports_tool_events`,
`supports_usage`, `supports_reasoning`, `supports_plan_events`,
`supports_file_change_events`, `supports_permission_callbacks`,
`supports_cancellation`, and `supports_structured_json_output`.

Treat these as bridge capabilities, not a protocol negotiation mechanism. They
tell Python callers what normalized events or controls a provider bridge can
currently expose.

## Permissions

Permission support is optional and provider-dependent. The shared models are
`PermissionRequest`, `PermissionOption`, `PermissionResponse`,
`PermissionOptionKind`, and `PermissionOutcome`. `PermissionBroker` provides a
small pending-request store, available from `py_agent_ctrl.actions`, for
integrations that need to resolve or cancel permission requests.

## Agent-Specific Methods

- Claude Code: `.with_permission_mode(...)`, `.with_allowed_tools(...)`
- Codex: `.with_sandbox(...)`, `.full_auto()`, `.dangerously_bypass()`, `.with_images([...])`
- OpenCode: `.with_agent(...)`, `.with_files([...])`, `.with_title(...)`, `.share_session()`
- Pi: `.with_provider(...)`, `.with_thinking(...)`, `.with_tools([...])`, `.with_extensions([...])`, `.with_skills([...])`
- Gemini: `.with_approval_mode(...)`, `.plan_mode()`, `.yolo()`, `.with_sandbox()`, `.with_allowed_tools([...])`

Provider-native mode helpers accept either strings or typed enums such as
`ClaudePermissionMode`, `CodexSandboxMode`, and `GeminiApprovalMode`. Invalid
mode values fail early.
